# Stick Shift Engine C API

> **Status: v0.1.0-beta.1.** The API below is the contract
> [`crates/stickshift-capi`](../crates/stickshift-capi) implements. It is **asynchronous in shape**: calls return immediately with a handle or a
> result code, resources move from *pending* to *ready* or *failed*, and completions arrive as
> events. In this beta most work still happens synchronously inside the calls (see
> [What may wait in the beta](#what-may-wait-in-the-beta)); later releases move it onto engine
> threads **without changing this API**.

The C API is a thin layer over the Rust crates (`stickshift-render`, `stickshift-render-api`,
`stickshift-assets`, `stickshift-math`). It covers graphics only. The host application owns the window or
view, the run loop, input, audio and game logic.

- Header: [`stickshift.h`](../crates/stickshift-capi/include/stickshift.h), generated by cbindgen from
  `crates/stickshift-capi` (plain C11, usable from C++).
- Libraries: `libstickshift.a` and `libstickshift.dylib` (install name `@rpath/libstickshift.dylib`).
- Swift: [`module.modulemap`](../crates/stickshift-capi/include/module.modulemap) next to the header,
  so `import StickShift` works.

## Conventions

- **Names.** Functions are `stickshift_<module>_<verb>`. Types are `StickShift<Name>`. Constants are
  `STICKSHIFT_<NAME>`. Every enum-like type is a fixed-width integer `typedef` with `#define`
  constants, so any value a C caller passes is defined behaviour (an unknown value is rejected
  with `STICKSHIFT_ERROR_INVALID_ARGUMENT`).
- **Math.** Right-handed, Y up; a camera looks down −Z. `StickShiftMat4` is **column-major**
  (`m[0..3]` is the first column), the same memory layout as Swift's `simd_float4x4`. Clip-space
  depth is Metal's `0..1`. Angles are radians unless a name says `_deg`.
- **Colour.** Linear RGB(A) floats in `0..1`. The engine tonemaps and encodes to sRGB on output.
- **2D overlay.** Pixel coordinates of the drawable, origin at the **top-left**, +y down.
- **Strings.** UTF-8, NUL-terminated. Strings passed in are copied before the call returns.
  Strings returned are owned by the library; each function says how long they stay valid.
- **Pointers.** Output pointers must be non-NULL unless documented as optional. Pointer
  arguments are only read during the call unless the docs say otherwise (`StickShiftData`, readback
  buffers).

## Concepts

### Contexts

A `StickShiftContext *` is the only opaque pointer type. It owns the Metal device, every resource,
the worker threads that load models, and the event queue. Create one per render target:

- **Layer context**: renders into a `CAMetalLayer` the host owns (from an `NSView`, a `UIView`
  in 0.2, or an `MTKView`'s layer). The engine sets the layer's `device`, `pixelFormat`
  (`BGRA8Unorm`) and `drawableSize`; the host keeps it in its view hierarchy and calls
  `stickshift_context_resize` when the view changes size.
- **Offscreen context**: `metal_layer = NULL`. Renders into a fixed-size texture whose pixels
  can be read back (`stickshift_frame_read_pixels_async`). Used for tests, thumbnails and tools.
- **Null backend**: `backend = STICKSHIFT_BACKEND_NULL`. No GPU at all: resources and frames are
  tracked, draws are counted, nothing is drawn, read-backs return zeros. For host-side unit tests
  on machines without a GPU. On non-Apple platforms it is the only backend.

A context is ready to render once `STICKSHIFT_EVENT_CONTEXT_READY` has been delivered. Before that,
resource creation is accepted (resources stay pending) and `stickshift_frame_acquire` returns
`STICKSHIFT_FRAME_SKIPPED`. In the beta the context is ready as soon as `stickshift_context_create`
returns, and the event is already queued.

### Handles and resource states

Everything a context owns, other than the context itself, is named by a **typed 64-bit handle**:

```c
typedef struct StickShiftMesh    { uint64_t id; } StickShiftMesh;
typedef struct StickShiftTexture { uint64_t id; } StickShiftTexture;
typedef struct StickShiftModel   { uint64_t id; } StickShiftModel;
typedef struct StickShiftFont    { uint64_t id; } StickShiftFont;
```

- `id == 0` is the null handle and never names a resource.
- An `id` encodes the handle kind, a slot index and a 32-bit generation. A handle is never
  reissued: once destroyed it stays invalid, and every later use returns
  `STICKSHIFT_ERROR_INVALID_HANDLE`. A slot whose generation would wrap is retired, not reused.
- Handles are only meaningful to the context that issued them.

Each resource is in one of these states (`stickshift_resource_state`):

| State | Meaning |
|---|---|
| `STICKSHIFT_RESOURCE_STATE_INVALID` | Not a live handle: never issued, destroyed, or another context's. |
| `STICKSHIFT_RESOURCE_STATE_PENDING` | Accepted; the work to make it usable has not finished. |
| `STICKSHIFT_RESOURCE_STATE_READY` | Usable in draws. |
| `STICKSHIFT_RESOURCE_STATE_FAILED` | The work failed. The handle stays valid (so you can read the state and destroy it) but draws using it are skipped. The failure event carries the reason. |

`*_create` and `*_load_*` calls return `STICKSHIFT_OK` and a handle **immediately**, with the resource
`PENDING` (or already `READY`, see the beta table). They return an error only for problems they
can detect at once: a bad argument, a full handle table, a busy context.

Destroying a resource invalidates its handle at once. GPU memory is released only after every
submitted frame that used it has finished (command buffers retain what they reference).
Destroying a pending resource cancels its work; its `StickShiftData` is still released (see
[Data ownership](#data-ownership)).

### Events and completion callbacks

Completions are reported as `StickShiftEvent`s:

```c
typedef struct StickShiftEvent {
    StickShiftEventType kind;    // STICKSHIFT_EVENT_*
    StickShiftResult    result;  // STICKSHIFT_OK, or why it failed
    uint64_t       object;  // the handle id the event is about, or 0
    uint64_t       frame;   // the frame number the event is about, or 0
    const char    *message; // detail for failures, or NULL
} StickShiftEvent;
```

| Event | When |
|---|---|
| `STICKSHIFT_EVENT_CONTEXT_READY` | The context can render. |
| `STICKSHIFT_EVENT_RESOURCE_READY` | A mesh, texture, model or font became `READY` (`object`). |
| `STICKSHIFT_EVENT_RESOURCE_FAILED` | It became `FAILED`; `result` and `message` say why. |
| `STICKSHIFT_EVENT_FRAME_COMPLETED` | The GPU finished frame `frame`. Frames complete in submission order. |
| `STICKSHIFT_EVENT_READBACK_COMPLETE` | The pixels requested for frame `frame` are in the caller's buffer. |
| `STICKSHIFT_EVENT_READBACK_FAILED` | They will never arrive (the frame was skipped or discarded). |

Events are delivered in two ways, **always on a host thread that is inside a `stickshift_*` call,
never on an engine thread**:

1. **Polling.** `stickshift_poll_events` copies queued events into a caller array. It also does the
   context's housekeeping: it uploads finished model loads, notices finished GPU frames and
   copies finished read-backs. Call it once per frame (or whenever you like).
2. **Per-call callbacks.** Functions that start work take an optional
   `const StickShiftCompletion *` (`{ callback, user }`). If given, that work's event goes to `callback` instead of
   the poll queue (each event is delivered exactly once). Callbacks run inside
   `stickshift_poll_events`, `stickshift_context_flush` or, in the beta, inside the call that started the
   work when it completes immediately.

`message` and the event pointer passed to a callback are valid until the callback returns
(callbacks) or until the next `stickshift_poll_events` on the context (polling). Callbacks may call
back into the same context, except `stickshift_context_destroy`.

### Data ownership

Bulk data (vertices, indices, pixels, model files) is passed as `StickShiftData`:

```c
typedef void (*StickShiftReleaseFn)(void *user, const void *ptr, size_t len);

typedef struct StickShiftData {
    const void     *ptr;
    size_t          len;      // bytes
    StickShiftReleaseFn  release;  // NULL: the engine copies the bytes before the call returns
    void           *user;
} StickShiftData;
```

- `release == NULL`: **copied**. The caller may free or reuse the buffer as soon as the call
  returns.
- `release != NULL`: **borrowed**, zero-copy. The bytes must stay valid and unchanged until the
  engine calls `release(user, ptr, len)`. It does so **exactly once**, from inside a `stickshift_*`
  call on the calling thread, after it no longer needs the bytes, and at the latest during
  `stickshift_context_destroy`.
- If the call that receives the data **fails**, the engine did not take it: `release` is not
  called and the caller still owns the buffer.

### Frames

A frame is recorded CPU-side and handed to the GPU as one unit:

```c
StickShiftFrame *frame;
if (stickshift_frame_acquire(ctx, &frame) == STICKSHIFT_OK) {
    stickshift_frame_set_camera(frame, &camera);
    stickshift_frame_draw_model(frame, car, &world, NULL);
    stickshift_frame_draw_text(frame, font, "Score 42", 16, 40, 24, white);
    stickshift_frame_submit(frame, NULL, &frame_number);
}
```

- `stickshift_frame_acquire` **never waits**. It returns `STICKSHIFT_FRAME_SKIPPED` when the GPU already
  has the maximum number of frames in flight (3), when the context is not ready yet, or when the
  drawable size is zero. Skip that tick's rendering and try again next tick. It returns
  `STICKSHIFT_ERROR_WRONG_STATE` if a frame is already open: one frame per context at a time.
- Recording calls (`stickshift_frame_draw_*`, `stickshift_frame_set_*`) only append to the frame. Nothing
  reaches Metal until `stickshift_frame_submit`.
- `stickshift_frame_submit` encodes and commits the frame and returns; it never waits for the GPU. It
  returns `STICKSHIFT_FRAME_SKIPPED` if the layer had no drawable to give (for example the window is
  hidden). Either way the frame is closed. `stickshift_frame_discard` closes it without rendering.
- **Camera and sun/sky are sticky**: they keep their last value across frames until set again.
  Within a frame, the last value set before submit applies to the whole frame (every draw, the
  sky and the shadow fit). Before the first set, the camera is the identity and the sun is
  `stickshift_sun_sky_default`.
- 3D draws are depth-tested. 2D quads and text composite on top of the 3D scene, in record
  order.
- **Draws and handle states.** A draw naming a `PENDING` or `FAILED` resource is not recorded:
  the call returns `STICKSHIFT_NOT_READY` and counts it in `StickShiftStats.draws_skipped`. A destroyed or
  unknown handle returns `STICKSHIFT_ERROR_INVALID_HANDLE`. A resource destroyed after a draw was
  recorded, but before submit, is dropped from the frame at submit and counted the same way.
- **Materials.** Meshes with the `POS_NORMAL_UV` layout sample `base_color_texture` (white if
  none) and multiply it by `base_color`. Meshes with the `POS_NORMAL_COLOR` layout take their
  colour from the vertices; `base_color` and the texture are ignored for them in the beta.
- **Colour spaces.** Lighting is linear. Create colour images (photos, painted albedo) with
  `STICKSHIFT_COLOR_SPACE_SRGB`: the sampler decodes them to linear before shading. Create data
  (an SDF font atlas, masks) with `STICKSHIFT_COLOR_SPACE_LINEAR`: it is sampled as stored. Model
  textures are sRGB automatically. `STICKSHIFT_FILL_TEXTURE` quads show the colours a texture stores
  in either colour space; font atlases and `STICKSHIFT_FILL_SDF` textures must be linear, and an sRGB
  one is refused with `STICKSHIFT_ERROR_INVALID_ARGUMENT`.

Frame numbers start at 1 and increase by one per submitted frame. `STICKSHIFT_EVENT_FRAME_COMPLETED`
reports them in order.

### Threading

- A context, and the frame it hands out, may be used from **any thread, but by one thread at a
  time**. A call that overlaps another call on the same context returns `STICKSHIFT_ERROR_BUSY` at
  once and does nothing; it never waits for the other call and never corrupts state.
- Different contexts are independent and may be used from different threads at the same time.
- Thread-safe, callable from anywhere at any time: `stickshift_api_version`, `stickshift_version_string`,
  `stickshift_result_name`, `stickshift_last_error_message`, the `stickshift_mat4_*` / `stickshift_quat_*` helpers,
  `stickshift_render_settings_default` and `stickshift_sun_sky_default`.
- Callbacks and `release` functions run on the thread that is inside the `stickshift_*` call that
  delivers them, never on an engine thread.
- In Swift, confine a context to one actor (for example `@MainActor`, or a render actor).

### Errors

Every fallible function returns a `StickShiftResult`. `STICKSHIFT_OK` (0) is success; small positive values
are non-error outcomes; negative values are errors:

| Code | Meaning |
|---|---|
| `STICKSHIFT_OK` | Done. |
| `STICKSHIFT_FRAME_SKIPPED` | No frame this time (see [Frames](#frames)). Not an error. |
| `STICKSHIFT_NOT_READY` | A resource the call needs is pending or failed; nothing was done. |
| `STICKSHIFT_ERROR_INVALID_ARGUMENT` | NULL where a pointer is required, a bad enum value, sizes that don't match. |
| `STICKSHIFT_ERROR_INVALID_HANDLE` | The handle is null, destroyed, of the wrong kind, or another context's. |
| `STICKSHIFT_ERROR_WRONG_STATE` | The call is not allowed now (no frame open, frame already open, …). |
| `STICKSHIFT_ERROR_BUSY` | Another call on this context is in progress. |
| `STICKSHIFT_ERROR_NO_DEVICE` | No Metal device (or Metal is unavailable on this platform). |
| `STICKSHIFT_ERROR_UNSUPPORTED` | Not supported by this context or build (e.g. read-back on a layer context, header/library version mismatch). |
| `STICKSHIFT_ERROR_IO` | A file could not be read. |
| `STICKSHIFT_ERROR_PARSE` | A glTF or image could not be decoded. |
| `STICKSHIFT_ERROR_LIMIT_EXCEEDED` | An engine limit was hit (see [Limits](#limits)). |
| `STICKSHIFT_ERROR_INTERNAL` | A bug in the engine (a Rust panic caught at the boundary). The context may be inconsistent; destroy it. |

On any error the call has no effect, and `stickshift_last_error_message()` returns a description. That
message is per-thread and valid until the next failing call on the same thread. It is never NULL
(an empty string when there is none). `stickshift_result_name(code)` returns the constant's name.

No panic, abort or exception ever crosses the C boundary.

## What may wait in the beta

The API never requires a call to wait. In the beta, a few calls still do bounded work on the
caller's thread, or can wait on the system. Every row changes in a later release without an API
change.

| Call | In the beta | Later |
|---|---|---|
| `stickshift_context_create` | Synchronous setup: creates the Metal device and compiles the shaders (tens to a few hundred ms). `CONTEXT_READY` is queued before it returns. | Setup runs on an engine thread; `CONTEXT_READY` arrives later. |
| `stickshift_mesh_create`, `stickshift_texture_create`, `stickshift_font_create` | Upload on the caller's thread before returning (bounded by the data size; textures do not wait for mipmap generation). The resource is `READY` on return; `RESOURCE_READY` is queued (or the callback runs before the call returns). Borrowed data is released before the call returns. | Uploads move to a transfer queue; resources become ready later. |
| `stickshift_model_load_file`, `stickshift_model_load_memory` | Return at once. File read, glTF parse and image decode run on a worker thread; the GPU upload happens in the next `stickshift_poll_events` (or `stickshift_context_flush`). | Uploads use Metal fast resource loading. |
| `stickshift_frame_acquire` | Never waits. | Same. |
| `stickshift_frame_submit` | Encodes the frame on the caller's thread (bounded CPU work) and takes the next drawable from the layer, which can wait (up to about a second if the window is hidden, then `STICKSHIFT_FRAME_SKIPPED`). Never waits for the GPU. | An engine render thread does the encoding and takes the drawable; submit only queues the frame, and the newest queued frame wins. |
| `stickshift_poll_events` | Bounded housekeeping plus your callbacks. | Same. |
| `stickshift_context_flush` | **Waits** for every load and every submitted frame to finish, then delivers their events. Tests and tools only. | Same. |
| `stickshift_context_destroy` | **Waits** for submitted frames to finish and for a model parse in progress to end. | Same. |

## Versioning and ABI

- There is **no ABI stability before 1.0**. Any release may change the API; the
  [CHANGELOG](../CHANGELOG.md) says how.
- `STICKSHIFT_API_VERSION` (a header constant) increases with every incompatible change.
  `stickshift_api_version()` returns the library's value. `StickShiftContextDesc.api_version` must be set to
  `STICKSHIFT_API_VERSION`: if it does not match the library, `stickshift_context_create` fails with
  `STICKSHIFT_ERROR_UNSUPPORTED`. That catches a header and a library from different releases.
- `stickshift_version_string()` returns the release, for example `"0.1.0-beta.1"`.

## Limits

| Limit | Value |
|---|---|
| Frames in flight | 3 |
| Texture size | 16384 × 16384 |
| Live handles per kind, per context | 16 777 215 |

```c
typedef struct StickShiftCamera {
    StickShiftMat4 view_projection;  // world -> clip
    StickShiftVec3 position;         // world-space eye, for specular
} StickShiftCamera;

typedef struct StickShiftSunSky {
    float sun_elevation_deg;      // 0 horizon .. 90 overhead
    float sun_azimuth_deg;        // from -Z (north) toward +X (east)
    float sun_color[3];
    float sun_intensity;
    float sky_fill;               // ambient fill, well below sun_intensity
    float sky_zenith_color[3];
    float sky_horizon_color[3];   // the fog fades toward this
} StickShiftSunSky;

typedef struct StickShiftMaterial {
    StickShiftColor   base_color;
    StickShiftTexture base_color_texture;  // {0}: none
} StickShiftMaterial;

typedef uint32_t StickShiftFill;  // STICKSHIFT_FILL_SOLID, STICKSHIFT_FILL_TEXTURE, STICKSHIFT_FILL_SDF

typedef struct StickShiftQuad {
    float x, y, width, height;   // pixels, origin top-left
    float u0, v0, u1, v1;        // texture rectangle (ignored for SOLID)
    StickShiftColor   color;          // tint; alpha blends
    StickShiftFill    fill;
    StickShiftTexture texture;        // for TEXTURE and SDF
} StickShiftQuad;
```

## Example

```c
#include "stickshift.h"

StickShiftContextDesc desc = {
    .api_version = STICKSHIFT_API_VERSION,
    .backend = STICKSHIFT_BACKEND_METAL,
    .metal_layer = layer,            // a CAMetalLayer * the host owns
    .width = 1280, .height = 720, .scale = 2.0f,
};
StickShiftContext *ctx;
if (stickshift_context_create(&desc, &ctx) != STICKSHIFT_OK) {
    fprintf(stderr, "stickshift: %s\n", stickshift_last_error_message());
    return 1;
}

StickShiftModel car;
stickshift_model_load_file(ctx, "car.glb", NULL, &car);   // returns at once; PENDING

// Each display tick:
StickShiftEvent events[16];
uint32_t n;
stickshift_poll_events(ctx, events, 16, &n);
for (uint32_t i = 0; i < n; i++) {
    if (events[i].kind == STICKSHIFT_EVENT_RESOURCE_FAILED)
        fprintf(stderr, "load failed: %s\n", events[i].message);
}

StickShiftFrame *frame;
if (stickshift_frame_acquire(ctx, &frame) == STICKSHIFT_OK) {
    StickShiftMat4 view = stickshift_mat4_look_at((StickShiftVec3){0, 3, 8}, (StickShiftVec3){0, 0, 0},
                                        (StickShiftVec3){0, 1, 0});
    StickShiftMat4 proj = stickshift_mat4_perspective(0.8f, 1280.0f / 720.0f, 0.1f, 200.0f);
    StickShiftCamera camera = { stickshift_mat4_mul(proj, view), {0, 3, 8} };
    stickshift_frame_set_camera(frame, &camera);

    StickShiftMat4 world = stickshift_mat4_identity();
    stickshift_frame_draw_model(frame, car, &world, NULL);  // STICKSHIFT_NOT_READY until it loads
    stickshift_frame_submit(frame, NULL, NULL);
}

// At shutdown:
stickshift_context_destroy(ctx);
```

## Building, linking and testing

**Build.** `cargo build --release -p stickshift-capi` writes `target/release/libstickshift.a` and
`target/release/libstickshift.dylib`; the header and module map are in `crates/stickshift-capi/include/`.
The Homebrew package installs all of them (`include/stickshift/`, `lib/`) with a `stickshift.pc`.

**Link dynamically** (simplest): `-I<include dir> -L<lib dir> -lstickshift`, and make the dylib
findable through an rpath (`-Wl,-rpath,<lib dir>`, or the app bundle's `Frameworks` directory).

**Link statically:** link `libstickshift.a` plus the system frameworks and libraries the Rust code
needs. `pkg-config --static --libs stickshift` prints them for an installed package; for a checkout,
rustc reports them:

```sh
cargo rustc -p stickshift-capi --lib --crate-type staticlib -- --print native-static-libs
```

On macOS that is `-framework Metal -framework QuartzCore -framework Foundation
-framework CoreGraphics -framework CoreFoundation -framework AppKit -lobjc -liconv`.
[`scripts/test-c-api.sh`](../scripts/test-c-api.sh) builds the C smoke test and
[`examples/c/offscreen.c`](../examples/c/offscreen.c) exactly this way.

**Swift.** Add the include directory to the import paths (`SWIFT_INCLUDE_PATHS` in Xcode, or
`-I` with `swiftc`), link `libstickshift`, and `import StickShift`. Pass the view's layer as
`Unmanaged.passUnretained(layer).toOpaque()` for `metal_layer`; the engine retains it.
Confine the context to one actor, since the busy guard rejects overlapping calls rather than
serialising them.

**Testing a host without a GPU.** Create the context with `STICKSHIFT_BACKEND_NULL`: every call
behaves as on Metal (handles, states, events, frames, stats), nothing is drawn, frames complete
as they are submitted and read-backs return zeros. That keeps host-side unit tests running on
machines without Metal, including CI runners.
